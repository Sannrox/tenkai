# Release notes: v0.9.1

Crate version: **`0.9.1`**. Tag: **`v0.9.1`**. Release candidate: `v0.9.1-rc.1`.

Pair with [release readiness](../release-readiness.md). Contributor credits
belong on the GitHub Release generated notes.

## Scope

Pre-1.0 patch after [v0.9.0](0.9.0.md). The server serves web console
[v0.4.0](https://github.com/Sannrox/tenkai-console/releases/tag/v0.4.0) at
`/ui/`, which shows and edits the 0.9.0 features: instance health, promotion
policy and pause/resume, automatic and selector holds, apply cancel, sealed
secret age, waivers and grace, labels, owners and notification endpoints,
approval briefs and rendered target changes, recall, upgrade pace, and paged
webhook deliveries. v0.9.0 shipped console v0.3.1.

Base: tag `v0.9.0` (`9a4ae8d`). Gate flags: `none`.

## Compatibility and migration

| Surface | Impact for 0.9.1 |
| --- | --- |
| Crate version | `0.9.0` → `0.9.1` for `tenkai` and every workspace crate |
| SQLite `SCHEMA_VERSION` | Remains **14**. No migration |
| HTTP, runtime, plan and contract versions | Unchanged from 0.9.0 |
| Web console | `ui/console.pin` moves from `v0.3.1` to `v0.4.0`. Same `tenkai.http.v1` contract; console types come from the signed Tenkai `v0.9.0` schema |
| GitHub Release assets | Same host names as 0.9.0 |

### Operator upgrade notes

1. Install `0.9.1` hosts from the GitHub Release after verifying `SHA256SUMS`
   and the attestation, or with `install.sh`. `tenkaictl --version` reports
   `tenkaictl 0.9.1`. Release servers serve console `v0.4.0` at `/ui/`.
2. Source builds with feature `ui` download `tenkai-console-v0.4.0.zip` and
   check its SHA-256 against `ui/console.pin`. `TENKAI_UI_BUNDLE` must point
   at the v0.4.0 zip.

### Rollback

Previous `0.9.0` binary plus the existing store. It serves console `v0.3.1`
again.
