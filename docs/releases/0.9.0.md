# Release notes: v0.9.0

Crate version: **`0.9.0`**. Tag: **`v0.9.0`**. Release candidate: `v0.9.0-rc.1`.

Pair with [release readiness](../release-readiness.md). Contributor credits
belong on the GitHub Release generated notes.

## Scope

Pre-1.0 minor after [v0.8.1](https://github.com/Sannrox/tenkai/releases/tag/v0.8.1).
Channels promote on their own after a soak with evidence (#1193), pace
upgrades over a time window (#1231), and recall a soaking release when health
fails (#1209). Instances report health after apply (#1207), and an environment
holds itself when many instances fail (#1210). Environments and releases carry
labels, and selectors stand in for environment lists (#1237). Exposure gains
advisory waivers, grace periods (#1236), and an optional scan-age gate
(#1269). Every plan carries an approval brief (#1253), command refusals name
the gate and the next action (#1258), and an operator can cancel a running
apply (#1220). The versioned HTTP API reads and writes these surfaces (#1281
to #1361). Tenkai publishes its own server and console as the signed catalog
product `tenkai-server` (#1262).

The server serves web console
[v0.3.1](https://github.com/Sannrox/tenkai-console/releases/tag/v0.3.1), the
same as 0.8.0. [v0.9.1](0.9.1.md) serves the console for these features.

Base: tag `v0.8.1` (`0c5818a`). Changes: `v0.8.1..v0.9.0` (`9a4ae8d`), 62
pull requests. Open release-blocking issues at crate-bump time: **none**.

Gate flags: `breaking`, `migration`. `migration` comes from the label on
#1193; no store or operator migration is required.

### Operator upgrade notes

1. **Install:** install `0.9.0` hosts from the GitHub Release after verifying
   `SHA256SUMS` and the attestation, or with `install.sh`. `tenkaictl
   --version` reports `tenkaictl 0.9.0`. The store opens without migration.
2. **HTTP clients (#1357, #1359):** upgrade clients that read labels or
   webhook delivery lists with the server. A 0.8 server refuses a hold that
   carries a selector (#1317) and answers 404 for the new routes.
3. **Promotion policy and pace (#1193, #1231, #1209):** nothing changes until
   a channel declares a policy or a pace. Gate-flagged trains refuse
   auto-promote. A committed promotion does not re-promote after an operator
   rollback.
4. **Health and holds (#1207, #1210):** apply observes instance health; a
   failure threshold on the environment holds it automatically.
5. **Exposure (#1236, #1269):** set `exposure.grace_ms` or
   `exposure.max_inventory_age_ms` on an environment, else its channel, to
   opt in. A waiver for advisory id `scan` covers a missing or stale scan.
6. **Pre-pull (#1266):** an approved plan blocked by a closed window pre-pulls
   digest-pinned images. Tag references are reported as failed and not
   pulled.
7. **`tenkai-server` product (#1262):** in-process apply refuses it on the
   coordinating host. Deliver it through an environment runtime or
   `tenkaictl self-upgrade`.

### Rollback

Previous `0.8.1` binary plus the existing store. 0.8.1 ignores the new graph
kinds and properties, so promotion policies, paces, labels, waivers, freezes,
recall ranges and owner routing stop taking effect until the upgrade is
repeated. A channel promotion already committed is not undone. Roll back HTTP
clients that read labels or delivery lists with the server.
