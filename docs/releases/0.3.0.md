# Release notes: v0.3.0

Crate version: **`0.3.0`**. Intended tag: **`v0.3.0`**.

Pair with [release readiness](../release-readiness.md). Contributor credits
belong on the GitHub Release generated notes.

## Scope

Pre-1.0 minor covering remote management lifecycle, preview environments,
governed package migrations, digest-bound catalog artifacts, fleet fairness
and release waves, same-version remediations, and the operator surfaces that
landed on `main` after published GitHub release
[v0.2.0](https://github.com/Sannrox/tenkai/releases/tag/v0.2.0).

Base: tag `v0.2.0` (`1cddbe0`, 2026-07-26). That tag is not an ancestor of
current `main` after the later history rewrite; these notes use the published
GitHub release as the operator baseline.

Open release-blocking issues at crate-bump time: **none**.

Tagging `v0.3.0` and publishing the GitHub Release stay a separate maintainer
action after this crate bump lands.

## Compatibility and migration

| Surface | Impact for 0.3 |
| --- | --- |
| Crate version | `0.2.0` → `0.3.0` |
| SQLite `SCHEMA_VERSION` | Tagged `v0.2.0` is **6**; 0.3 opens as **11**. Opening an existing community DB migrates automatically. Newer DBs fail closed |
| Runtime / auth / federated / model / plan / provider contracts | Documented `*_CONTRACT_VERSION` / `PLAN_FORMAT_VERSION` remain 1 |
| Management lifecycle | Additive `tenkai.management-lifecycle.v1` (`MANAGEMENT_LIFECYCLE_API_VERSION = 1`) |
| HTTP runtime JSON | Unknown fields fail closed |
| Optional Postgres hub | Feature `postgres`; `TENKAI_POSTGRES_URL`; schema-per-tenant; not the community default |
| Multi-replica | `--replica-count > 1` requires store `shared_replica_state`; durable tick fence when Postgres is configured |
| `high_availability` capability | **Still not claimed**; the flag remains fail-closed without it |
| Toolchain | `rust-version = "1.96.1"` |
| Defaults | Signing/approval fail closed; tenant mode / enterprise flags default off |

### Operator upgrade notes

1. **Embedded / SQLite:** run `tenkaictl backup` first. Install 0.3.0 binaries
   and open the existing `.tenkai-state` database. The store migrates
   `SCHEMA_VERSION` 6 → 11 (provider-outbox indexing, observation-time
   selection, typed hub/spoke records). Community remains single-writer.
2. **Remote HTTP clients:** requests that send unknown JSON fields now fail
   closed. Development bypass flags (`--allow-unsigned-development`,
   `--allow-unapproved-development`) stay embedded-only; a remote request
   that carries a bypass field is rejected.
3. **Remote catalog and plan verbs:** authenticated management-lifecycle
   routes cover publish, promote, subscribe, recall, plan, approve, apply,
   and rollback. See [management lifecycle](../management-lifecycle.md) and
   [ADR 0030](../decisions/0030-remote-management-lifecycle.md). Runtime
   tokens cannot call those operations.
4. **Optional provider hosts:** vendored Sekai/Chisei contracts moved to the
   1.0 façade (#211, #213). Pin a compatible sekai-chisei revision.
   Tenkai remains recoverable without the provider unless policy requires
   its evidence.
5. **Optional multi-tenant hub:** enable `postgres`, set
   `TENKAI_POSTGRES_URL`, follow
   [postgres-tenant-store.md](../postgres-tenant-store.md). Do not
   co-locate IdP databases.
6. **Multi-replica hubs:** follow
   [multi-replica-hub-runbook.md](../multi-replica-hub-runbook.md). Prefer
   one active writer plus a shared durable fence; do not share community
   SQLite files.

### Rollback

Previous binary plus restore of the pre-upgrade Tenkai-owned SQLite backup
(embedded) or Postgres `pg_restore` (hub), then re-inject tokens from the
secret store. Recovery never depends on sekai-chisei.

## User-visible changes

### Added

- Versioned remote management lifecycle: catalog publish / promote /
  subscribe / recall and plan / approve / apply / rollback
  ([management lifecycle](../management-lifecycle.md); #393–#398)
- Preview environments from a content-addressed branch pin
  ([preview environments](../preview-environments.md); #399)
- Governed package migrations, including remote parity
  ([package migrations](../package-migrations.md); #312, #358)
- Digest-bound OCI artifact refs and digest-bound layers in signed offline
  bundles (#386, #387)
- Kubernetes server-side apply; live worker-pool replacement from
  lifecycle observations (#389, #372)
- Durable release waves; fleet fairness isolation; thousand-environment
  workload (#293, #304, #302)
- Same-version remediations; change-set closure pins; independent prompt
  packages and Workshop modules (#282, #294, #296, #311)
- Connectivity-class upgrades; fixed-replica Shikigami worker pools
  (#297, #295)
- External delivery adapters that leave operational authority with Tenkai
  (#308)
- Bounded recovery diagnostic bundle; allowlisted OTLP traces keyed by
  operation identity (#370, #391)
- Versioned machine-readable CLI results; bounded terminal outcome
  inspection and export (#171, #200, #205)
- Observation host binary `tenkai-worker-lifecycle-fixture`

### Changed

- HTTP JSON bodies reject unknown fields (#434)
- Client façade and gate evidence use the Sekai 1.0 / evaluation-projection
  contracts (#211–#213)
- Module splits under the 300-line threshold preserve public contracts

### Fixed

- Plan index poison, retarget, no-op persistence, preview teardown, tenant
  fleet join, and Postgres-in-Tokio fail-closed paths (#175–#176,
  #317–#404)

### Security

- JWT delivery RBAC and deploy-environment scrubbing (#268)
- Software-executor diagnostic URI userinfo redaction (#278)
- Management capability required for promotion and canary repair (#273,
  #275)
- Executable dependency pinning (#196)
- Fail-closed signing, plan approval, tenant non-disclosure, and capability
  gates preserved
- Remote management rejects development-bypass fields

### Migration

- SQLite `SCHEMA_VERSION` 6 → 11 from tagged `v0.2.0`
- Additive remote management-lifecycle routes; community embedded path
  remains the default

## Out of scope for 0.3

- Advertising product `high_availability` capability
- Catalog service extraction
- Identity-plane DB co-location
- Creating tag `v0.3.0` in this crate-bump change
