# Release notes: v0.8.0

Crate version: **`0.8.0-rc.1`**. Tag: **`v0.8.0-rc.1`** (pre-release).

Pair with [release readiness](../release-readiness.md). Contributor credits
belong on the GitHub Release generated notes.

## Scope

Pre-1.0 minor after [v0.7.1](https://github.com/Sannrox/tenkai/releases/tag/v0.7.1).
Products run as named instances that depend on each other through declared
contracts (ADR 0043, ADR 0044). The environment runtime runs the built-in
executors (#1124, #1129, #1133), delivers sealed secrets (ADR 0045), and
issues and rotates workload certificates with peer grants derived from
dependency bindings (ADR 0046). Operators on a host sign in through host
identity on a Unix socket (ADR 0047). Unsubscribed instances are removed by
an approved plan (ADR 0049). A channel head can be removed on its own
(#1177). The server serves web console
[v0.3.1](https://github.com/Sannrox/tenkai-console/releases/tag/v0.3.1)
at `/ui/`.

Base: tag `v0.7.1` (`e541e7a`). Changes: `v0.7.1..v0.8.0-rc.1`. Open
release-blocking issues at crate-bump time: **none**.

Gate flags: `breaking`, `migration`.

## Compatibility and migration

| Surface | Impact for 0.8.0 |
| --- | --- |
| Crate version | `0.7.1` → `0.8.0-rc.1` for `tenkai` and every workspace crate |
| SQLite `SCHEMA_VERSION` | **13 → 14**, keyed by instance (#1044). Older binaries refuse the migrated store |
| Hub PostgreSQL | Tenant schema stamp **3**, additive DDL run once per tenant schema (#1099). `tenkai_reconcile_tick_claims` is unused (#1157) |
| HTTP contract | Id stays `tenkai.http.v1`. Additive routes and fields for instances, secrets, identity, drift, attempts and channel removal. Results accept unknown fields (#1175). `promote` returns the release digest and takes `expected_head` (#1176) |
| Runtime / auth / federated / model / plan / provider contracts | Documented `*_CONTRACT_VERSION` / `PLAN_FORMAT_VERSION` remain 1. New step kinds and runtime capabilities are advertised; older runtimes and appliers fail them closed |
| Manifest | Optional `[deploy.identity]` (#1159), `[config]` (#1113), dependency contracts (#1036 to #1045). Older servers refuse them |
| Signed statements | Signing goes through one content signer with one key per family (#1141). The production profile refuses file keys (#1142, #1147, #1152) |
| Feedback | Registration attests `tenkai.feedback_observation.v1@1.0.0` (#1105) |
| Web console | `ui/console.pin` moves from `v0.2.0` to `v0.3.1`. Same `tenkai.http.v1` contract |
| GitHub Release assets | Same host names as 0.7.1 |
| Linux hosts | glibc 2.28+ on x86-64 |
| Toolchain | `rust-version = "1.96.1"` |
| Rust library API | Broad breaking changes; each `!` pull request carries a Breaking section |
| Defaults | Signing, approval, trust and sealing fail closed. Tenant mode and enterprise flags default off for community SQLite |

### Operator upgrade notes

1. **Install:** install `0.8.0-rc.1` hosts from the GitHub pre-release
   after verifying `SHA256SUMS` and the attestation, or with `install.sh`.
   `tenkaictl --version` reports `tenkaictl 0.8.0-rc.1`. Upgrade every
   server, runtime and host applier before using any new manifest, step or
   secret feature below.
2. **Store migration (#1044):** the first 0.8.0 start migrates SQLite from
   schema 13 to 14. It first writes a verified pre-migration copy beside the
   store, or refuses to start. Keep that copy until you no longer need
   rollback.
3. **PostgreSQL hubs (#1099):** each tenant schema gets additive DDL (stamp
   3) on first use. Once every replica runs 0.8.0, drop
   `tenkai_reconcile_tick_claims` (#1157).
4. **Instances (#1044, #1045):** existing records become the default
   instance of their product. `env subscribe --instance` and HTTP
   `instance` are optional and default to the product name.
5. **Unsubscribe (#1153):** `env unsubscribe` needs `--version` while a
   release is recorded for the instance. The next approved plan removes a
   non-host instance. Helm removals need Helm 3.13 or later.
6. **Manifests:** declare `[deploy.identity]` (#1159) or `[config]` (#1113)
   only after every server and runtime runs 0.8.0.
7. **Sealed secrets (#1099, #1103, #1116, #1126, #1131, #1140, #1148):** set
   `TENKAI_RUNTIME_APPROVAL_POLICY` on each runtime before the first
   `tenkaictl secret set`. The file must be owned by the runtime user and
   not group- or world-writable. Set the first sealed value only after every
   server is upgraded. Host targets need the applier spool on tmpfs, with
   swap off or encrypted.
8. **Workload identity (#1155, #1159, #1162 to #1171):** issuer, rotation
   and peer-grant plans go only to runtimes that advertise the matching
   capability. The first plan after upgrade re-renders certificate holders
   once (#1164). Until it runs, rollbacks and restarts of a caller of a
   certified provider are refused.
9. **Host identity (#1035):** install writes `host-grants.toml` and creates
   the `tenkai-viewer`, `tenkai-operator` and `tenkai-admin` groups and the
   `/run/tenkai` socket directory. TCP still requires a bearer or assertion.
10. **Spoke standby (#1156):** `tenkaictl spoke-standby promote` takes
    `--environment`; `--state` is the restored SQLite store; every member
    passes the same `--lease-dir`. `spoke-standby.json` is no longer read.
    The promotion statement is written to `<store>.promotion.json`.
11. **Feedback (#1104 to #1106):** `TENKAI_FEEDBACK_PROVIDER_REGISTRATION`
    must attest
    `evidence_type=tenkai.feedback_observation;schema=tenkai.feedback_observation.v1@1.0.0`.
    Keep `feedback.observation@1.0.0` on the plane until no older replica
    remains.
12. **Trust (#1141, #1142, #1147, #1152):** the production profile refuses
    file signing keys. Provision a hardware-backed key per family before
    switching profiles.
13. **HTTP clients (#1175):** a client from before 0.8.0 still refuses a
    result field it does not know. Upgrade clients with the server.
14. **Support bundles (#1107):** verify bundles with 0.8.0 or newer.
15. **Channel heads (#1177):** `tenkaictl channel remove` clears one
    product's head on one channel and stops its delivery there. Installed
    software stays until unsubscribed.
16. **Web console:** release servers serve console `v0.3.1` at `/ui/`. It
    shows instances and bindings, peer grants, workload identity, the
    issuer, attempt history, drift and per-step apply results, and reads
    them only when the server returns them. Source builds with feature `ui`
    download the new zip and check its SHA-256.

### Rollback

Previous `0.7.1` binary. The SQLite schema changed, so 0.7.1 refuses the
migrated store. To roll back:

- stop the server, restore the verified pre-migration copy over the store,
  and start 0.7.1. Changes made after the upgrade are lost;
- roll back runtimes and host appliers with their server. The 0.7.1
  server brings back console `v0.2.0`;
- set `TENKAI_FEEDBACK_PROVIDER_REGISTRATION` back to its 0.7.1 value;
- a PostgreSQL tenant schema keeps the additive stamp 3 DDL, which 0.7.1
  ignores. Do not drop `tenkai_reconcile_tick_claims` until rollback is no
  longer needed.

## User-visible changes

### Added

- Named product instances and dependency contracts (#1036 to #1045, #1098)
- Sealed secrets for runtimes and host targets (#1099, #1103, #1116, #1126,
  #1131, #1134, #1140, #1148)
- Workload identity: issuers, certificate rotation and peer grants from
  dependency bindings (#1155, #1159, #1162 to #1171)
- Host identity on a Unix socket (#1035)
- The environment runtime runs the built-in executors (#1124, #1129, #1133)
- Approved removal of unsubscribed instances (#1153)
- Feedback webhooks (#1104 to #1106)
- Drift reporting (#1114), attempt history and structured causes (#1115,
  #1118), config schema (#1113), workloads in support bundles (#1107)
- `tenkaictl channel remove` (#1177)
- Web console `v0.3.1` at `/ui/`

### Changed

- One content signer and one key per family; production refuses file keys
  (#1141, #1142, #1147, #1152)
- `promote` returns the release digest and takes `expected_head` (#1176)
- Operation results accept unknown fields (#1175)
- Spoke standby keeps its state in the operational store (#1156)
- The catalog lease is the only execution claim (#1160); the reconcile tick
  fence is dropped (#1157)

### Fixed

- See the CHANGELOG `v0.8.0-rc.1` section for every fix in the range.

### Security

- Sealed values open only with a hardware-backed sealing key on an approved
  runtime (#1134, #1140)
- Host sign-in maps local groups to grants without a network credential
  (#1035)
- Signing keys are separated by family (#1141)

### Migration

- GATE:mig. SQLite `SCHEMA_VERSION` 13 → 14 with a verified pre-migration
  copy. PostgreSQL tenant schema stamp 3. HTTP contract id stays
  `tenkai.http.v1`.

## Out of scope for 0.8.0

- Items moved to the 0.9.0 milestone, including #1173
