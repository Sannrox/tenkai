# Release notes: v0.7.1

Crate version: **`0.7.1`**. Tag: **`v0.7.1`**.

Pair with [release readiness](../release-readiness.md). Contributor credits
belong on the GitHub Release generated notes.

## Scope

Pre-1.0 patch on published GitHub release
[v0.7.0](https://github.com/Sannrox/tenkai/releases/tag/v0.7.0). Operators
who run `kubernetes-inprocess` get the lease-renew path that was missing
from the signed `v0.7.0` tag (#986 / #991), waits that require the applied
revision (#987), diagnosed causes kept when a lease is lost (#992), and a
fail-closed process default when `TENKAI_SOFTWARE_EXECUTOR` is unknown
(#990). The reference cluster example keeps ServiceLB and local-path storage
(#984).

Base: tag `v0.7.0` (`23deec8`). Changes: `v0.7.0..v0.7.1`. Open
release-blocking issues at crate-bump time: **none**.

Gate flags: `none`.

### Operator upgrade notes

1. **Embedded / SQLite:** install `0.7.1` hosts from the GitHub Release after
   verifying `SHA256SUMS` and the attestation, or with the attached
   `install.sh`. The schema stays 13, so a 0.7.0 store opens without
   migration. `tenkaictl --version` reports `tenkaictl 0.7.1`. See
   [release binaries](../release-binaries.md).
2. **kubernetes-inprocess long waits (#986, #982):** apply renews the
   environment lease (and any held wave or topology leases) while the
   executor runs, at a quarter of the shortest TTL and at most every 10 s.
   The executor's own timeout bounds the step, not lease expiry. A 0.7.0
   host still loses the lease under a wait longer than the TTL and reports
   only the lease-release error.
3. **In-process upgrades (#987):** a Deployment, StatefulSet, or DaemonSet
   step succeeds only when the applied revision is the one serving, not when
   leftover old pods keep `Available`. Crash-loop diagnosis of the new
   revision still fails the wait. See
   [software executor](../software-executor.md).
4. **Lost-lease causes (#992):** if renewal still fails, the error names the
   last observed workload causes first and the lost lease after them, the
   same way a timeout already does. Diagnosis lists ReplicaSets and pods in
   the environment namespace; without that `list` the wait continues on
   conditions and names the read error.
5. **`TENKAI_SOFTWARE_EXECUTOR` (#990):** an unknown or uninstalled value
   refuses `tenkai-server` and embedded hosts at start, with the same
   message shape as a missing declared executor. Unset (or `shell`) remains
   the process default. `/readyz` advertises `software_executor:<kind>` for
   the default that actually runs.
6. **Reference cluster (#984):** the example k3s unit no longer disables the
   service load balancer or local-path storage. An operator who already
   installed that product publishes a newer version and applies it as an
   upgrade. A `LoadBalancer` Service in the environment namespace binds host
   ports; claims without a class get local-path volumes.
7. **Outcome / feedback export, signed statements, host releases:** same
   0.7.0 upgrade steps. This patch does not change those contracts.

### Rollback

Previous `0.7.0` binary plus the existing Tenkai-owned SQLite (embedded) or
Postgres (hub) store. No schema change in this patch. Recovery never depends
on sekai-chisei.

- 0.7.0 ignores `failed_target_error.<product>`.
- 0.7.0 still treats an unknown `TENKAI_SOFTWARE_EXECUTOR` as shell for
  undeclared releases.
- A 0.7.0 host can report an in-process upgrade complete while old pods keep
  the Deployment Available, and a wait longer than the apply lease TTL still
  fails as a lease-release error.

## User-visible changes

### Fixed

- Apply renews the environment lease during in-process (and other software
  executor) waits, and names the workload failure cause instead of only the
  lease-release error (#986, #982)
- In-process Kubernetes upgrades wait for the applied revision, not merely
  `Available` on leftover pods (#996, #987)
- A stalled in-process wait that loses the apply lease keeps the diagnosed
  workload causes (#999, #992)
- The reference cluster example keeps the service load balancer and
  local-path storage so in-cluster releases can bind volumes and serve
  traffic (#984, #983)

### Security

- Unknown or uninstalled `TENKAI_SOFTWARE_EXECUTOR` refuses at start instead
  of falling back to shell for undeclared releases (#998, #990)

### Migration

- None. `SCHEMA_VERSION` remains 13. HTTP contract id stays
  `tenkai.http.v1`. Gate flags: none.
