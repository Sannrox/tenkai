# Release notes: v0.10.0

Crate version: **`0.10.0`**. Tag: **`v0.10.0`**. Release candidate: `v0.10.0-rc.1`.

Pair with [release readiness](../release-readiness.md). Contributor credits
belong on the GitHub Release generated notes.

## Scope

Pre-1.0 minor after [v0.9.1](0.9.1.md). Tenkai stands alone
([ADR 0064](../decisions/0064-tenkai-stands-alone.md)): it owns its record
types and store, refuses remote provider mode, and admits evaluation gates
from signed evidence pushed to it (#1586 to #1589).

Operators gain time-boxed, audited debug sessions on an instance with
quorum-approved elevation (#1561 to #1568); instance stop and start (#1529);
adoption of unmanaged workloads (#1530); recall limited to named
environments, range exclusions and an instance-count threshold (#1550 to
#1552); and upgrades onto an advisory-recalled release that lowers exposure
(#1535). Releases gain config presets (#1458), environment-wide config values
(#1461), preview environments (#1549) and cluster namespaces (#1537) over
HTTP v1, OS image updates across a reboot (#1416, #1444, #1449, #1453, #1504),
a provision executor bound to the saved plan (#1540), and the Apple container
engine (#1539). Planning checks artifact availability (#1442), reconciliation
evaluates only environments that changed (#1576), and delivery spans link
into one trace (#1448).

Hosts ship for `linux-aarch64` and as `.deb`, `.rpm` and a Homebrew formula
(#1447). The server serves web console
[v0.6.0](https://github.com/Sannrox/tenkai-console/releases/tag/v0.6.0) at
`/ui/` (#1590).

Base: tag `v0.9.1`. Changes: `v0.9.1..v0.10.0`. Gate flags: `breaking`. No
pull request in the range carries `risk:migration`; the hub tenant schema
migrates on start without operator action.

### Operator upgrade notes

1. **Install:** install `0.10.0` hosts from the GitHub Release after verifying
   `SHA256SUMS` and the attestation, or with `install.sh` or a system
   package. `tenkaictl --version` reports `tenkaictl 0.10.0`.
2. **Order:** every runtime agent must run 0.7.0 or later before the server
   is upgraded (#1436). Upgrade runtimes together with the server: older
   runtimes fail closed on adopt, stop, start, cluster namespace, provision
   and OS image steps.
3. **Remote provider mode (#1586, #1587, #1588):** unset
   `--provider-mode remote`, `--outcome-provider chisei`,
   `--feedback-provider chisei` and their settings first, or the server does
   not start. An operator still on remote mode initializes a Tenkai-owned
   store.
4. **Evaluation gates (#1586):** `[gate].eval_suite` passes only on ingested
   signed evaluation evidence, on every host including embedded. Push the
   evidence before relying on the gate.
5. **Finish the rolling upgrade first:** older servers refuse recall
   `environments`, range `exclusions` and policy `debug_sessions`, and an
   older replica that reads a stored recall treats a scoped recall as
   fleet-wide and ignores exclusions, so it recalls versions the operator
   meant to protect. Scope recalls, add exclusions and set `debug_sessions`
   only after every replica runs 0.10.
6. **Federated identity (#1387):** a replay cache full of live assertion ids
   answers 401 until some expire.
7. **Source builds:** feature `ui` downloads `tenkai-console-v0.6.0.zip` and
   checks its SHA-256 against `ui/console.pin`. `TENKAI_UI_BUNDLE` must point
   at the v0.6.0 zip.

### Rollback

Remove `debug_sessions` from the approval policy file first: 0.9.1 refuses
the field and does not start. Then run the previous `0.9.1` binary on the
existing store. 0.9.1 ignores the new tables,
columns and properties, so debug sessions, stop state, presets, environment
config values, recall scope and exclusions, and cluster namespaces stop
taking effect. It treats scoped recalls as fleet-wide, recalls excluded versions, and
withholds grant rules that name `debug`. Remote provider mode works again
only with the store it used before. It serves console `v0.4.0` again.
