# Release notes: v0.6.0

Crate version: **`0.6.0`**. Tag: **`v0.6.0`**.

Pair with [release readiness](../release-readiness.md). Contributor credits
belong on the GitHub Release generated notes.

## Scope

Pre-1.0 minor release on published GitHub release
[v0.5.0](https://github.com/Sannrox/tenkai/releases/tag/v0.5.0). Adds
engine-selected `model_runtime` execution, signed model-runtime evidence and
eval-gated promotion, post-apply SLO health gates and signed apply webhooks,
signed offline install bundles with a companion chunk store, and platform JWT
plus OIDC in one process. Also covers hub PostgreSQL as the sole enterprise
store, runner certificates, grant rules, and HA / dark-site / spoke-standby
profiles that landed after `v0.5.0`.

Base: tag `v0.5.0`. Changes: `v0.5.0..v0.6.0`, through #896.

## Compatibility and migration

| Surface | Impact for 0.6.0 |
| --- | --- |
| Crate version | `0.5.0` → `0.6.0` for `tenkai` and every workspace crate |
| SQLite `SCHEMA_VERSION` | **12 → 13**. Typed catalog rows, `change_events`, grant rules, runtime enrollment and certificates. GATE:mig |
| Hub Postgres schema | Follows 13. PostgreSQL is the sole enterprise hub store (#746) |
| HTTP contract | Id stays `tenkai.http.v1`. New routes are additive (events, grants, runners, exports, observed runtime, delivery holds) |
| Auth | One process accepts platform JWT and OIDC (#595). Existing token validation is unchanged. Agent `act` claims cannot start named mutations (#660) |
| Mixed versions | Upgrade servers before clients that call new routes. A `0.5.0` host cannot open a schema-13 store, and refuses manifests with `[inventory]` or `[topology]` and trust roots with signer windows |
| Web console | `ui/console.pin` unchanged (`v0.2.0`) |
| GitHub Release assets | Same names as 0.5.0, plus `tenkai-runtime` / `tenkai-runtime-guard` from the runtime crate |
| Toolchain | `rust-version = "1.96.1"` |
| Defaults | Signing/approval fail closed; tenant mode / enterprise flags default off for community SQLite |

### Operator upgrade notes

1. **Embedded / SQLite:** install `0.6.0` hosts from the GitHub Release after
   verifying `SHA256SUMS` and the attestation. Opening an existing store
   migrates `PRAGMA user_version` 12 → 13. Backup the store first. A `0.5.0`
   binary refuses a schema-13 file. `tenkaictl --version` reports
   `tenkaictl 0.6.0`. See [release binaries](../release-binaries.md).
2. **Enterprise hub:** PostgreSQL is the only hub store (#746). Embedded and
   spoke hosts stay SQLite. `TENKAI_POSTGRES_URL` is invalid on those hosts.
   Pre-0029 graph files migrate into typed schema 13 rows.
3. **Auth (#595, #660):** JWT and OIDC share one process. Existing OIDC and
   management-token validation still applies. Agent-initiated mutations named
   in the `act` claim are refused.
4. **`model_runtime`:** engine selection (vLLM, TGI, NIM, MLX, classical)
   fetches weights into the verified cache and plans against accelerator
   facts. Isolated environments refuse `hf://` without a mirror (#702).
   Promotion needs passing eval evidence (#620).
5. **Offline bundles:** a signed bundle plus companion chunk store can
   first-install a site, carry hosts, docs, OCI layers, and model weights,
   and build deltas against a named base release. Stage, verify, and import
   through the server.
6. **TLS and enterprise profile:** `tenkai-server` can listen with native TLS
   and optional mutual TLS (#766). The enterprise profile refuses to start
   while an authoritative surface is missing (#768).
7. **Runner trust:** runtime agents enroll through a runner CA. Credentials
   are single-use and revocable, and can bind to signed host preflight
   evidence.
8. **Signer validity windows (#863):** trust-root signers may carry
   `not_before` / `not_after`. 0.6.0 checks the window against the
   verifier's clock at verification time, not at signing time, for stored
   artifacts too: the installed revocation list at every start (a failure
   stops `tenkai-server` and `tenkaictl`), backup restore, audit exports,
   support bundles, offline bundles, and the stored release signature that
   `tenkai-server` re-verifies against `TENKAI_RELEASE_TRUST_ROOTS` before a
   non-local deploy. Once a signer passes `not_after`, what it signed stops
   verifying, so do not set `not_after` on a key whose signed artifacts you
   still need. Checking stored artifacts at their signing time is tracked
   for 0.7.0 in #865.
9. **`tenkai.terminal_outcome.v1` (#855, #867):** tenant-mode hubs now
   export terminal outcomes. Their payload carries `tenant_id` and their
   `target_external_id` is `<tenant>:<deployment_id>` instead of
   `<deployment_id>`, under the unchanged schema version `1.0.0`. A consumer
   schema registered from the earlier field list refuses tenant-mode
   outcomes. Add `tenant_id` before enabling export on a tenant-mode hub.
10. **Feedback capture on tenant-mode PostgreSQL hubs (#868):** committed
    deployment outcomes write no `tenkai.feedback_observation.v1` record on
    these hubs, with no error. SQLite hubs capture them. Do not rely on
    observation history from a tenant-mode PostgreSQL hub.
11. **Manifest sections:** `[inventory]` (#856) and `[topology]` (#701) are
    new top-level manifest sections. A `0.5.0` hub or spoke refuses a
    release that declares either with an unknown-field error. Upgrade every
    host that receives a release before publishing one.
12. **Feedback export (#875):** opt-in delivery of captured feedback
    observations as evidence through the provider outbox. Off by default
    (`--feedback-provider` / `TENKAI_FEEDBACK_PROVIDER`, `disabled`).
    Enabling it needs embedded application state,
    `TENKAI_FEEDBACK_PROVIDER_URL`, `TENKAI_FEEDBACK_NAMESPACE` and an exact
    `TENKAI_FEEDBACK_PROVIDER_REGISTRATION`. While it is disabled,
    `tenkai-server` refuses to start if any of those feedback settings or
    `TENKAI_FEEDBACK_PROVIDER_TOKEN` is set. Disabled or unavailable export
    does not interrupt deploy or rollback.

### Rollback

Previous `0.5.0` binary plus a store restored from a pre-upgrade backup.
A schema-13 store does not open on `0.5.0`. HTTP contract id is unchanged, so
clients that only use 0.5.0 routes can talk to a 0.6.0 server after the store
migrates. Before running a `0.5.0` binary, remove `not_before` / `not_after`
from its trust-root files; it refuses files that carry them (ADR 0039).

## User-visible changes

### Added

- Platform JWT and OIDC in one process (#595)
- `model_runtime` engine selection, verified weight fetch, and accelerator
  planning (#598, #599, #612), with vLLM, TGI, NIM, MLX, and classical
  executors (#606, #757, #760, #742, #734)
- Signed model-runtime evidence and eval-gated promotion (#618, #619, #620)
- Post-apply SLO health gates and signed apply webhooks (#621, #622)
- Signed offline install bundle, companion chunk store, delta bundles, and
  server-side stage/verify/import (#624, #625, #715, #731, #740, #756, #833)
- Native TLS listener with optional mutual TLS (#766)
- Runner CA enrollment, revocable runtime credentials, and runner registry
  (#630, #752, #758, #772, #773)
- Stored grant rules and a management-token API to edit them (#839, #840)
- Hub PostgreSQL catalog graph, atomic outbox, and a fenced multi-replica
  writer (#746, #748, #853, #855)
- HA, dark-site, and spoke-standby profiles (#857, #861, #862)
- Signer validity windows in trust roots (#863)
- Opt-in feedback observation export through the provider outbox (#875)
- Authorized tenant export of release pins as a digest-pinned bundle
  section (#882)
- Signed family release manifests, gate flags that hold channels, and
  family release trains (#894, #895)

### Changed

- SQLite and hub schema 12 → 13
- Enterprise hub uses PostgreSQL only (#746)
- Isolated environments refuse `hf://` origin without a mirror (#702)

### Fixed

- One-image Docker releases recreate only the changed container (#669)
- Guard failures are distinct from deployment command failures (#794)
- One fencing generation for remote `--generation` and environment inspect
  (#703)
- Concurrent environment changes no longer clobber connectivity upgrade
  records (#713)
- Fence loss cannot complete a running plan (#845)
- Fenced deploys run with `/bin/sh` and keep a bounded stderr snippet (#881)
- rustls-webpki, webpki-roots, and ctutils advisories (#712)

### Migration

- GATE:mig. `SCHEMA_VERSION` 12 → 13. HTTP contract id stays
  `tenkai.http.v1`. Backup before upgrade. `0.5.0` cannot open the migrated
  store.

- Releasing the console. It has no changes since `v0.2.0`
