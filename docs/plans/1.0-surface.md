# 1.0 listed surface

ADR 0040: from 1.0, a break of this list needs a major bump; until then a
minor may break it. Either way, CI fails an unmarked removal. Items not on
this list may change without a bump.

## HTTP v1

Checked-in contract: [`api/tenkai-http-v1.schema.json`](../../api/tenkai-http-v1.schema.json).
It lists public `/v1` routes (not `/v1/runtime/*`), health, OIDC discovery,
and the request and response schemas. CI compares it to the last final `v*`
tag.

## CLI `--output json-v1`

Checked-in contract: [`api/tenkai-command-result-v1.schema.json`](../../api/tenkai-command-result-v1.schema.json).
That is the `tenkai.command-result/v1` envelope. Commands that emit it, and
the success-path exceptions (`explain` report JSON, `env history` page JSON),
are in [command results](../command-results.md). CI compares the envelope
schema to the last final `v*` tag. Human CLI text and `fleet watch --json`
are not listed.

## Runtime protocol

Wire: `proto/tenkai/runtime/v1`. Narrative:
[runtime protocol v1](../runtime-protocol-v1.md). CI already runs `buf
breaking` against the last final `v*` tag.

## Manifest

Fields in [the manifest](../manifest.md). Publication still refuses unknown
keys. There is no separate JSON Schema gate for TOML.

## Signature and approval envelopes

- Release signature `tenkai.release-signature.v1`:
  [release signing](../release-signing.md)
- Plan approval `tenkai.plan-approval.v1`:
  [plan approval](../plan-approval.md)

Canonical signed bytes are the contract; extra JSON keys stay refused.

## Breaking CI

A pull request that removes a listed HTTP or json-v1 field, or a listed HTTP
route, fails the `Schema breaking` job unless its title is `type!:` or its
body has a `## Breaking` or `## Upgrade` section **and** it carries
`risk:breaking`. Additive fields and routes pass. Proto and Rust public API
use the same marker ([CONTRIBUTING.md](../../CONTRIBUTING.md)).
