## v0.4.2 (2026-10-07)

Crate version: **`0.4.2`**. Tag: **`v0.4.2`**.

Pair with [release readiness](https://github.com/Sannrox/tenkai/blob/v0.4.2/docs/release-readiness.md). Contributor credits
belong on the GitHub Release generated notes.

### Scope

Pre-1.0 patch on published GitHub release
[v0.4.1](https://github.com/Sannrox/tenkai/releases/tag/v0.4.1). Operators get
web console
[v0.2.0](https://github.com/Sannrox/tenkai-console/releases/tag/v0.2.0) at
`/ui/`, which adds environment subscribe, catalog publish, promote, and recall,
and a reconcile tick over the existing `tenkai.http.v1` routes. The workspace
is split into crates (#523), which changes source-build feature flags.

Base: tag `v0.4.1` (`bf0f835`). Open release-blocking issues at crate-bump
time: **none**. Follow-up #511 stays open.

### Compatibility and migration

| Surface | Impact for 0.4.2 |
| --- | --- |
| Crate version | `0.4.1` → `0.4.2` for `tenkai` and every workspace crate |
| SQLite `SCHEMA_VERSION` | Remains **12**. No migration |
| Hub Postgres schema | Remains 12 |
| Runtime / auth / federated / model / plan / provider contracts | Documented `*_CONTRACT_VERSION` / `PLAN_FORMAT_VERSION` remain 1 |
| HTTP contract | Id stays `tenkai.http.v1`. Console v0.2.0 requires exactly this contract |
| Web console | `ui/console.pin` moves from `v0.1.0` to `v0.2.0` |
| Source builds | `ui` and `postgres` are `tenkai-server` features (#523): community `--features tenkai-server/ui`, hub `-p tenkai-server --features postgres,ui` |
| GitHub Release assets | Same names as 0.4.1: community `ui` hosts, hub `tenkai-server-postgres-<platform>`, `tenkai-http-v1.schema.json`, `SHA256SUMS`, and attestations for `linux-x86_64` and `darwin-aarch64` |
| Toolchain | `rust-version = "1.96.1"` |
| Defaults | Signing/approval fail closed; tenant mode / enterprise flags default off |

#### Operator upgrade notes

1. **Embedded / SQLite:** install `0.4.2` hosts from the GitHub Release after
   verifying `SHA256SUMS` and the attestation. No store migration.
   `tenkaictl --version` reports `tenkaictl 0.4.2`. See
   [release binaries](https://github.com/Sannrox/tenkai/blob/v0.4.2/docs/release-binaries.md).
2. **Web console:** management actions in the console call the same lifecycle
   routes as `tenkaictl` and need the `management` capability. Nothing changes
   in server authorization. A credential refused by the server loses that
   scope's console controls for the session.
3. **Source builds:** replace `--features ui` with `--features tenkai-server/ui`
   for the workspace, or build `-p tenkai-server --features ui`. The hub
   build is `cargo build --release --locked -p tenkai-server --features postgres,ui`.
   `TENKAI_UI_BUNDLE` still skips the download and still enforces the pinned
   checksum.

#### Rollback

Previous `0.4.1` binary plus the existing Tenkai-owned SQLite (embedded) or
Postgres (hub) store. No schema change in this patch; the previous binary
serves console v0.1.0 again. Recovery never depends on sekai-chisei.

### User-visible changes

#### Added

- Web console v0.2.0: subscribe an environment to a product channel; publish,
  promote, and recall releases with signing kept outside the browser; request
  one reconcile tick and read its per-environment report

#### Changed

- Workspace split into `tenkai-wire`, `tenkai-http`, `tenkai-server`,
  `tenkaictl`, `tenkai-executor`, and `tenkai-postgres`; `ui` and `postgres`
  are now `tenkai-server` features (#523)

#### Fixed

- Web console no longer sends a management action clicked while the browser
  was offline when it reconnects; the outcome shows as unknown instead

#### Migration

- None. `SCHEMA_VERSION` remains 12. HTTP contract id stays `tenkai.http.v1`.

### Out of scope for 0.4.2

- A route that lists a caller's grants for the console
- Advertising product `high_availability` capability
- Extra platforms or crates.io
- Rewriting `docs/releases/0.4.1.md`
- #511 (export operation-bound feedback observations)

## v0.4.0 (2026-10-04)

Crate version: **`0.4.0`**. Tag: **`v0.4.0`**.

Pair with [release readiness](https://github.com/Sannrox/tenkai/blob/v0.4.0/docs/release-readiness.md). Contributor credits
belong on the GitHub Release generated notes.

### Scope

Pre-1.0 minor on published GitHub release
[v0.3.2](https://github.com/Sannrox/tenkai/releases/tag/v0.3.2). Operators get
the pinned web console, OIDC access-token authentication, environment
retirement, the published `tenkai.http.v1` contract, and fail-closed hub
Postgres TLS.

Base: tag `v0.3.2` (`7733d05`). Open release-blocking issues at crate-bump
time: **none**. Follow-up #511 stays open.

### Compatibility and migration

| Surface | Impact for 0.4.0 |
| --- | --- |
| Crate version | `0.3.2` → `0.4.0` |
| SQLite `SCHEMA_VERSION` | **11 → 12**. Opening an existing store migrates automatically (`environments.retired_at` plus an active-row index). Newer DBs fail closed |
| Hub Postgres schema | Same 11 → 12 `retired_at` migration |
| Runtime / auth / federated / model / plan / provider contracts | Documented `*_CONTRACT_VERSION` / `PLAN_FORMAT_VERSION` remain 1 |
| HTTP contract | Id stays `tenkai.http.v1`. Additive inspect and OIDC discovery fields. Unset response optionals are omitted |
| Optional Postgres hub | Same feature and `TENKAI_POSTGRES_URL`; non-loopback hosts require verified TLS |
| Spoke / CLI embedded | Still refuse `TENKAI_POSTGRES_URL` (ADR 0029) |
| GitHub Release assets | Community hosts built with `--features ui` for `linux-x86_64` and `darwin-aarch64`, plus `tenkai-http-v1.schema.json`, `SHA256SUMS`, and GitHub artifact attestations |
| Toolchain | `rust-version = "1.96.1"` |
| Defaults | Signing/approval fail closed; tenant mode / enterprise flags default off |

#### Operator upgrade notes

1. **Embedded / SQLite:** run `tenkaictl backup` first. Install `0.4.0`
   community hosts from the GitHub Release after verifying `SHA256SUMS` and
   the attestation, or `cargo build --release --locked`. Opening the existing
   store migrates `SCHEMA_VERSION` 11 → 12. `tenkaictl --version` reports
   `tenkaictl 0.4.0`. See [release binaries](https://github.com/Sannrox/tenkai/blob/v0.4.0/docs/release-binaries.md).
2. **`tenkai-server` community host:** the GitHub asset is built with
   `--features ui` and serves the pinned console at `/ui/`. See
   [run tenkai-server](https://github.com/Sannrox/tenkai/blob/v0.4.0/docs/run-tenkai-server.md#open-the-web-console) and
   [sign in with Keycloak](https://github.com/Sannrox/tenkai/blob/v0.4.0/docs/console-sign-in-with-keycloak.md).
3. **OIDC:** set `TENKAI_OIDC_CONFIG` to a trust TOML file. That setting is
   exclusive with `TENKAI_JWT_VERIFIER_CONFIG`. Tenkai verifies access tokens
   as a resource server. See
   [configure server authentication](https://github.com/Sannrox/tenkai/blob/v0.4.0/docs/configure-server-authentication.md).
4. **Remote HTTP clients:** regenerate types from
   `tenkai-http-v1.schema.json` on the GitHub Release. Unset optionals are
   omitted. Rejected management bearers return **401** with
   `WWW-Authenticate`; authenticated callers without access still return
   **403**. Environment inspect adds `latest_plan.digest`, `maintenance`, and
   `constraints` when the store has them.
5. **Environment-bound management:** OIDC rules with `environment = …` and
   environment-scoped tokens may call reconcile and package-migration apply /
   resume / rollback only for that environment. Fleet-wide reconcile stays
   with unbound management credentials.
6. **Tenant-mode hub:** keep `--features postgres`, `TENKAI_POSTGRES_URL`,
   management credentials, and JWT or OIDC trust. Non-loopback Postgres URLs
   require verified TLS (`sslmode=disable` fails closed before dialing). Hub
   Postgres hosts remain
   `cargo build --release --locked --features postgres --bin tenkai-server`.
7. **Spoke / community:** leave `TENKAI_POSTGRES_URL` unset. That refuse is
   unchanged.

#### Rollback

Previous `0.3.2` binary plus restore of the pre-upgrade Tenkai-owned SQLite
(embedded) or Postgres (hub) store, then re-inject tokens from the secret
store. A migrated 0.4.0 store is `SCHEMA_VERSION` 12; 0.3.2 fails closed on
newer schemas. Recovery never depends on sekai-chisei.

#### Operator upgrade notes

1. **Embedded / SQLite:** rebuild binaries; existing `.tenkai-state` continues
   if schema version still matches. Run `tenkaictl backup` before major upgrades.
2. **Optional multi-tenant hub:** enable `postgres`, set `TENKAI_POSTGRES_URL`,
   follow [postgres-tenant-store.md](https://github.com/Sannrox/tenkai/blob/v0.2.0/docs/postgres-tenant-store.md). Do not
   co-locate IdP databases.
3. **Multi-replica hubs:** follow
   [multi-replica-hub-runbook.md](https://github.com/Sannrox/tenkai/blob/v0.2.0/docs/multi-replica-hub-runbook.md). Prefer
   single active writer + shared durable fence; do not share community SQLite files.
4. **Development bypasses** (`--allow-unsigned-development`,
   `--allow-unapproved-development`) remain explicit and audited — not
   production defaults.

#### Rollback

Previous binary + restore of Tenkai-owned SQLite backup (embedded) or Postgres
`pg_restore` (hub), then re-inject tokens from the secret store. Recovery never
depends on sekai-chisei.

### User-visible changes

#### Added

- Fleet status, fleet drift watch, multi-environment rollout waves
- Environment capability facts + local hardware inventory probe
- Runtime inventory fact heartbeat (`POST …/inventory`, optional disable)
- Helm and native Kubernetes (kubectl) software apply paths
- Model runtime control plane, llama.cpp reference path, canary × model_runtime
- Staged products: `policy_bundle`, `eval_suite`, `agent_definition`
- Optional advisory plan priors (local file + OutcomeProvider projection)
- Remote HTTP GateProvider for chisei-compatible eval decisions
- AuthStack management HTTP, federated identity accept path, JWT EdDSA assertion verifier
- Tenant isolation on management HTTP surfaces; in-memory and optional Postgres tenant stores
- Postgres hub `shared_replica_state` (single-active-writer), multi-host tick fencing, durable Postgres fence
- Optional OpenMetrics scrape (`--enable-metrics` / `GET /metrics`)
- Multi-replica hub ops runbook; ADR 0008 / 0009

#### Changed

- README Status tracks second-gen fleet, hub, and staged-product surface
- Capability negotiation remains fail-closed for multi-replica / HA / tenant flags

#### Security

- Fail-closed signing, plan approval, tenant non-disclosure, and capability gates preserved
- Diagnostics, metrics, and fleet baselines must not carry management/runtime tokens

#### Migration

- Optional only: Postgres feature, multi-replica flags, metrics flag; community path unchanged

### Out of scope for 0.2

- Advertising product `high_availability` capability
- Catalog service extraction
- Identity-plane DB co-location
